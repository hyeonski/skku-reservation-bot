# 핸드오프: 사이드패널 채팅 UI (P1 + P2 + P3)

> **포함된 디자인 파일은 HTML로 만든 디자인 레퍼런스**입니다. 의도된 모양과 동작을 보여주는 프로토타입이지, 그대로 복사할 프로덕션 코드가 아닙니다. 이 패키지의 작업은 **이 디자인을 기존 `extension/` 코드베이스의 React + TypeScript + Vite 환경에서 재현**하는 것입니다.

## 충실도 (Fidelity)

**하이파이 (Hi-fi)** — 색상·타이포·간격·인터랙션 모두 최종안입니다. 픽셀 단위로 맞춰 구현하세요. 디자인 토큰은 `03-design-tokens.md`, 정확한 값은 `prototype/styles.css`를 참조.

## 무엇을 만드는가

성균관대 GLS 공간예약 크롬 확장의 **메인 채팅 UI**. 기존 popup을 **사이드패널로 마이그레이션**하면서 다음 화면들을 새로 만듭니다:

| Phase | 화면/플로우 | 구현 우선순위 |
|---|---|---|
| — | 사이드패널로의 마이그레이션 (manifest, 진입점) | 🟢 P1 (선결) |
| P1 | 온보딩 2스텝 (환영 → 사용 예시) | 🟢 P1 |
| P1 | 세션 목록 + 새 대화 선택기 | 🟢 P1 |
| P1 | 채팅 — 슬롯필링 → 후보 검증 → 추천 카드 → 신청 메타 → 초안 → 제출 | 🟢 P1 |
| P1 | 채팅 내 인라인 GLS 로그인 카드 (필요 시 / 만료 시) | 🟢 P1 |
| P1 | 채팅 실패 분기 — 조건 조정해서 재시도 | 🟢 P1 |
| P2 | 채팅 인라인 추천 — "지난번처럼 ... 작성할까요?" | 🟡 P2 |
| P3 | 세션 목록 상단 패턴 리마인드 배너 | 🔵 P3 |

P2/P3는 별도 페이즈이므로 UI는 만들되 데이터 연결은 P1 완료 후 진행하세요.

1. **`01-architecture-change.md`** — popup → 사이드패널 전환. manifest 변경, 새 진입점, 기존 popup 코드 처리.
2. **`02-screens.md`** — 화면별 레이아웃 스펙 (온보딩, 세션 목록, 채팅).
3. **`03-design-tokens.md`** — 색·타입·간격·반경 토큰 전체 값.
4. **`04-components.md`** — 채팅 메시지, 추천 카드, 신청서 카드, 검색 진행 카드, GLS 로그인 카드 등 컴포넌트 단위 스펙.
5. **`05-state-machine.md`** — 채팅 phase 머신, 분기, 메시지 시퀀스, GLS 자동화 상태와의 동기화.
6. **`06-mock-vs-real.md`** — 프로토타입에서 mock으로 처리된 것과, 실제 서버/GLS 자동화로 대체할 매핑.

## 프로토타입 보기

`prototype/index.html`을 브라우저에서 열면 인터랙티브 데모가 뜹니다. 우하단 **Tweaks** 토글로 모든 시나리오 분기를 점프할 수 있습니다 (성공 / 실패 / 로그인 필요 / 세션 만료 / 온보딩 / 세션 목록).

## 한 가지 큰 변경

원래 PRD/DECISIONS는 **popup** 진입점으로 설계되어 있지만, 이 디자인은 **사이드패널 (Chrome 114+)** 로 마이그레이션합니다. 이유:

- popup은 클릭 외 영역 누르면 사라짐 → GLS 자동화가 도는 동안 사용자가 진행 상황을 볼 수 없음
- 사이드패널은 브라우저 우측에 고정 → GLS 페이지(왼쪽)에서 행 하이라이트, 폼 자동 채움이 일어나는 동안 사용자가 옆에서 실시간으로 관찰 가능
- D-026의 "popup이 닫혀도 background SW가 진행하고 알림으로 완료 통지" 원칙은 사이드패널로도 그대로 적용됨 (사이드패널은 탭 전환·창 닫기 시 닫힘)

이는 **manifest.json 변경**과 **새 진입점 디렉터리 생성**을 필요로 합니다. 상세는 `01-architecture-change.md`.
