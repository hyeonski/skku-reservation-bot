# SKKU 공간예약 에이전트 — 사용자 관점 E2E 테스트 케이스

> 작성 관점: **완전한 사용자 입장 (블랙박스)**. 내부 구현·코드·상태명·API를 전혀 모른다고 가정한다.
> 각 케이스는 "사용자가 **무엇을 이루고 싶은지(목표)**"에서 출발해, 사용자가 직접 보고 하는 행동과 눈으로 확인 가능한 결과만으로 기술한다.
> 형식: 목표 / Given(상황) / When(내가 하는 행동) / Then(내가 기대하는 것)

---

## 0. 이 테스트의 원칙

### 0.1 누가 테스트하는가
성균관대 학생회 간부·동아리 임원(예약 담당자). 컴퓨터에 특별히 능숙하지 않을 수 있고, GLS 예약을 "귀찮은 잡무"로 여긴다. 이 사람이 "도와준다길래 써봤다"는 마음으로 행동한다.

### 0.2 무엇을 검증하는가 (사용자가 체감하는 것만)
- 내가 말한 대로 **알아듣는가**
- 내가 **타이핑·클릭을 덜 하게** 되는가 (수동보다 빠르고 편한가)
- 내가 **모르는 사이에 엉뚱한 예약**이 들어가지 않는가 (확인 없이 제출 안 함)
- 막혔을 때 **무엇을 해야 하는지 알려주는가** (그냥 멈추거나 침묵하지 않음)
- 다음에 또 쓰고 싶은가

### 0.3 기술 용어를 쓰지 않는다
"슬롯", "intent", "API", "상태머신", "메시지 타입" 같은 말은 이 문서에 등장하지 않는다. 대신 "내가 인원을 안 적었다", "추천 공간이 화면에 뜬다", "확인 버튼을 누른다"처럼 **사용자가 실제로 보고 하는 일**로만 쓴다.

### 0.4 기대 결과를 쓰는 방식
- ✅ 좋게: "회의실 이름·정원·시간이 한눈에 보인다"
- ❌ 피함: "RecommendationCard가 렌더된다", "automationStatus가 candidate_found가 된다"
- 화면에 보이는 글자·버튼·카드·알림처럼 **사용자 눈에 잡히는 것**으로 적는다.

### 0.5 우선순위
- 이 문서의 우선순위는 개발 페이즈(P0/P1/P2 등)가 아니라, **Phase 2까지 구현된 기능 범위 안에서 무엇부터 테스트할지**를 나타낸다.
- 비율은 **우선순위 1:2:3 = 약 70:20:10**으로 둔다. 전체 129개 기준 `129 × 70/20/10% = 90.3 / 25.8 / 12.9`이므로, 정수 반올림 분포는 **우선순위 1 90개 / 우선순위 2 26개 / 우선순위 3 13개**다.
- **우선순위 1 (70%)**: 핵심 예약 흐름, 신뢰·안전, 자주 쓰는 표현, 실패 시 앱을 믿기 어려운 케이스. 알파테스트·회귀에서 우선 실행한다.
- **우선순위 2 (20%)**: 편의·복구·관리 흐름. 우선순위 1이 안정된 뒤 사용성을 확인할 때 실행한다.
- **우선순위 3 (10%)**: 저빈도 상황, Phase 3 이후 후보, 범위 밖 요청, 있으면 좋은 안내 품질. 시간 여유가 있거나 관련 변경이 있을 때 실행한다.

### 0.6 케이스 ID
`UC-<번호>` (User Case). 목표 단위로 묶고, 같은 목표의 변형은 소문자 접미사(a/b/c)로 표기. **ID는 고정자산** — 삭제·흡수되어도 번호를 재배열하지 않는다(상호참조 보존). 삭제 내역은 부록 D 로그 참조.

### 0.7 이 문서가 검증하는 범위 (Phase 2 기준선)
이 앱은 **Phase 2까지 구현**된 상태다. 따라서 "성공해야 한다"고 보는 범위는 아래로 한정한다.
- **Phase 1**: 자연어 예약 요청 → 빈 공간 탐색 → 신청서 자동 작성·제출 (end-to-end)
- **Phase 2**: 예약 이력 저장 → "지난번처럼" 재사용·추천

**명시적 범위 밖**(성공 기대 없음): Phase 3 정기 패턴 리마인드 알림, Phase 4 자동 반복 실행, Phase 5 다른 시스템(도서관 등), 제출 후 반려 감지·재신청, 제출된 예약의 자동 취소·변경, 고급 탐색/비교 UX, 학교 정책 상세 추론. → 이런 요청은 *우아하게 거절하는지*(Graceful Decline)만 검증한다.

### 0.8 케이스 분류 태그
우선순위(1~3)와 별개로, 각 케이스가 무엇을 보는지 구분한다.
- **Core** — Phase 1~2 핵심 기능. 반드시 성공해야 한다. (별도 표기 없으면 기본값)
- **Graceful Decline** — 기능은 지원하지 않지만 사용자가 시도할 법한 요청. *성공이 아니라 "정직하게 안내하는지"*를 본다.
- **Robustness** — 에러·환경·입력·화면 안정성. "깨지지 않는지"를 본다.
- 🛡️ **안전(Safety)** — 기능/오류/운영 여부와 별개로 *잘못된 예약·오역·정보 노출·무단 제출 같은 사고를 막는* 케이스. 한눈에 추출하도록 따로 표시.

**Graceful Decline**: UC-92, UC-95, UC-108, UC-113(→Phase 4 후보), UC-114, UC-124(→Phase 4 후보)
**Phase 3 후보**: UC-51~55, UC-81
**🛡️ 안전(Safety)**: UC-21, UC-33, UC-37, UC-39, UC-40, UC-62, UC-63, UC-64, UC-70, UC-71, UC-79, UC-97, UC-98, UC-101, UC-107, UC-115, UC-121, UC-122, UC-130, UC-131
**Robustness**: UC-16, UC-17, UC-18, UC-65~69, UC-72~78(오류 전달 전반), UC-89, UC-90, UC-99, UC-100, UC-102, UC-103, UC-104, UC-118, UC-123, UC-127, UC-128, UC-129, UC-132
> UC-70·71은 위 🛡️안전으로 분류(중복 제외). 위 Graceful Decline/Phase 3 후보/Robustness에 없는 나머지는 기본적으로 **Core**이며, Safety는 사고 방지용 강조 태그로 중복될 수 있다.

## 1. 처음 써본다 — "이게 뭐 하는 거지?"

### UC-01 — 처음 열었을 때 뭘 하는 앱인지 이해된다 (우선순위 1)
- **목표**: 설치하고 처음 열었을 때, 설명 없이도 "아, 말로 공간 예약하는 거구나"를 안다.
- **Given** 방금 설치하고 처음 연다.
- **When** 앱을 연다.
- **Then** 이 앱이 무엇을 해주는지(말로 공간 예약), 어떻게 말하면 되는지 예시가 보인다. 첫 화면에서 막히지 않고 다음으로 넘어갈 수 있다.

### UC-02 — 안내를 건너뛰고 바로 쓸 수 있다 (우선순위 2)
- **목표**: 이미 감 잡았으니 소개를 스킵하고 바로 예약하고 싶다.
- **When** 소개 화면에서 "건너뛰기"를 누른다.
- **Then** 바로 사용 화면으로 넘어가 입력을 시작할 수 있다.

### UC-03 — 두 번째부터는 소개가 안 뜬다 (우선순위 2)
- **목표**: 매번 똑같은 소개를 다시 보고 싶지 않다.
- **Given** 한 번 소개를 보고 사용을 시작한 적이 있다.
- **When** 앱을 닫았다가 다시 연다.
- **Then** 소개 화면 없이 바로 쓸 수 있는 화면이 나온다.

### UC-04 — 보여준 예시 문구가 실제로 통한다 (우선순위 2)
- **목표**: 소개에서 본 예시처럼 말하면 진짜 되는지 믿고 싶다.
- **When** 소개에 나온 예시 문구를 그대로 따라 입력한다.
- **Then** 그 문구로 예약이 정상 진행된다 (예시가 빈말이 아니다).

## 2. 핵심 목표 — "공간을 예약해줘"

### UC-05 — 한 문장으로 말하면 알아서 진행한다 (우선순위 1)
- **목표**: 다 적었으니 더 묻지 말고 바로 찾아줬으면.
- **Given** 사용 화면.
- **When** "다음 주 화요일 18시부터 2시간, 20명 회의실 잡아줘"라고 입력한다.
- **Then** 나에게 추가로 되묻지 않고 곧바로 빈 공간을 찾기 시작한다. 내가 말한 날짜·시간·인원이 정확히 반영돼 있다.

### UC-06 — 빠뜨린 게 있으면 딱 그것만 물어본다 (우선순위 1)
- **목표**: 대충 말해도, 부족한 건 알아서 채워달라고 물어봐줬으면.
- **Given** 사용 화면.
- **When** "공간 예약하고 싶어"처럼 두루뭉술하게 입력한다.
- **Then** 한 번에 하나씩(예: 먼저 인원) 자연스럽게 물어보고, 내가 답하면 다음 부족한 정보를 물어본다. 같은 걸 두 번 묻지 않는다.
- **And** "한 20~30명쯤", "스무 명 안팎"처럼 범위·어림수로 말하면, 필요한 경우 "최대 몇 명으로 잡을까요?"처럼 확인한다.

### UC-07 — "내일", "다음 주 화요일" 같은 말을 알아듣는다 (우선순위 1)
- **목표**: 날짜를 일일이 YYYY-MM-DD로 계산해서 적기 싫다.
- **When** "오늘", "내일", "모레", "이번 주 금요일", "다음 주 월요일"처럼 입력한다.
- **Then** 오늘 기준으로 올바른 실제 날짜로 이해한다 (주말/주 경계도 헷갈리지 않는다).

### UC-08 — 시간을 다양하게 말해도 통한다 (우선순위 1)
- **목표**: "2시부터 4시까지"든 "2시부터 2시간"이든 편한 대로 말하고 싶다.
- **When** "내일 오후 2시부터 4시까지 8명" / "내일 14시부터 2시간 8명" 둘 다 시도한다.
- **Then** 두 표현 모두 같은 의미로 알아듣고 진행한다.

### UC-09 — 특정 건물/캠퍼스를 지정할 수 있다 (우선순위 1)
- **목표**: 우리 동아리방 근처 건물에서만 잡고 싶다.
- **When** "다음 주 수요일 19시 2시간 15명 율전 학생회관" 또는 "명륜 600주년기념관"처럼 건물을 지정한다.
- **Then** 그 건물(또는 캠퍼스) 안에서만 찾아준다. 엉뚱한 캠퍼스 공간을 들이밀지 않는다.

### UC-10 — 한 줄로 다 말하면 가장 빠르다 (우선순위 1, 지표)
- **목표**: 수동 예약보다 확실히 빠르다고 느끼고 싶다.
- **When** "다음 주 화요일 18시 2시간 20명 학생회 회의" 완전한 문장을 입력한다.
- **Then** 되물음 없이 진행되고, 직접 GLS 메뉴를 헤매는 것보다 체감상 훨씬 빠르다.

## 3. 말귀를 알아듣는다 — 자연어 이해 (사용자 체감)

### UC-11 — 마음이 바뀌면 고쳐 말할 수 있다 (우선순위 1)
- **목표**: "아 20명이 아니라 30명이네" 정정하고 싶다.
- **Given** 직전에 인원·시간을 말해둔 상태.
- **When** "아니 30명으로"라고 한다.
- **Then** 인원만 30명으로 바뀌고 날짜·시간은 그대로 유지된다 (처음부터 다시 묻지 않는다).

### UC-12 — 한 번에 여러 개를 고칠 수 있다 (우선순위 1)
- **When** "30명으로 바꾸고 시간은 19시부터 1시간으로"라고 한 문장에 여러 변경을 말한다.
- **Then** 인원·시작시간·길이가 모두 한 번에 반영된다.

### UC-13 — "다른 곳 보여줘"가 통한다 (우선순위 2)
- **목표**: 추천받은 공간이 마음에 안 들어 다른 데를 보고 싶다.
- **Given** 추천 공간이 화면에 떠 있다.
- **When** "다른 곳 보여줘"라고 한다.
- **Then** 내가 말한 조건은 유지한 채 다른 공간을 찾아 보여준다.
- **And** (Graceful Decline) "여러 개 같이 보여줘 / 비교해서 보여줘"처럼 후보 목록을 요청해도, 후보를 길게 늘어놓지 않고 한 곳씩 제안하며 "한 곳씩 보여드려요"라고 안내한다 (한 곳씩 흐름 — D-013).

### UC-14 — "그만할래"가 통한다 (우선순위 2)
- **목표**: 하다 말고 그만두고 싶다.
- **When** "그만할래" 또는 "취소"라고 한다.
- **Then** 진행이 멈추고, 나를 계속 졸라대지 않는다. 다음에 새로 시작할 수 있다.

### UC-15 — 엉뚱한 잡담엔 선을 긋는다 (우선순위 1)
- **목표**: 실수로 딴소리해도 이상한 예약이 들어가지 않길.
- **When** "오늘 점심 뭐 먹지?"처럼 무관한 말을 한다.
- **Then** "저는 공간 예약을 도와드려요" 식으로 부드럽게 안내하고, 예약을 진행하지 않는다.

### UC-16 — 구어체·오타·축약도 웬만하면 알아듣는다 (우선순위 1)
- **목표**: 정확한 맞춤법으로 안 적어도 통했으면.
- **When** "담주 화욜 여섯시 스무명" 처럼 줄여/구어체로 입력한다.
- **Then** 합리적으로 알아듣거나, 애매하면 확인차 한 번 물어본다 (그냥 무시하거나 멈추지 않는다).

### UC-17 — 말이 안 되는 입력은 바로잡아준다 (우선순위 1)
- **목표**: 내가 실수로 이상하게 적어도 엉뚱하게 예약되지 않길.
- **When** "어제 14시 10명"(지난 날짜) / "25시" / "0명" / "-5명"처럼 비현실적으로 입력한다.
- **Then** 그대로 받아들이지 않고 다시 물어보거나 바로잡아 준다.

### UC-18 — 빈 입력·이상한 입력에도 안 죽는다 (우선순위 1)
- **When** 공백만 보내거나, 이모지·특수문자만, 또는 아주 긴 문장을 보낸다.
- **Then** 앱이 멈추거나 깨지지 않고, 무시하거나 다시 입력하라고 안내한다.

## 4. 딱 맞는 공간을 찾아준다 — 탐색 (사용자 체감)

### UC-19 — 찾는 동안 진행 상황이 보인다 (우선순위 1)
- **목표**: 멈춘 건지 찾는 중인지 알고 싶다.
- **When** 조건을 다 말해 탐색이 시작된다.
- **Then** "찾는 중"이라는 게 화면으로 느껴진다 (진행 표시 등). 무반응으로 가만히 있지 않는다.

### UC-20 — 가능한 공간을 한 곳 추천해준다 (우선순위 1)
- **목표**: 후보를 잔뜩 늘어놓지 말고, 일단 가능한 한 곳을 보여줬으면.
- **When** 조건에 맞는 빈 공간이 있다.
- **Then** 공간 이름·건물·정원·예약하려는 날짜/시간이 한눈에 보이는 추천이 뜬다. 채팅창이 수십 개 후보로 도배되지 않는다.

### UC-21 — 그 공간이 정말 비어 있는 것만 추천한다 (우선순위 1)
- **목표**: 추천받아 신청했는데 이미 찬 곳이면 헛수고다.
- **When** 추천을 받는다.
- **Then** 추천된 시간대에 수업·다른 예약·대여로 겹치지 않는, 실제로 비어 있는 공간만 추천된다.

### UC-22 — 조건에 맞는 곳이 없으면 솔직히 말해준다 (우선순위 1)
- **목표**: 없으면 없다고 빨리 알려줬으면.
- **When** 모든 공간이 다 차 있거나 조건에 맞는 게 없다.
- **Then** "조건에 맞는 공간이 없어요" 같이 분명히 알려주고, 조건을 바꿔보라고 제안한다 (무한 로딩/침묵 금지).

### UC-23 — 인원이 비현실적이면 헛탐색하지 않는다 (우선순위 2)
- **When** "500명"처럼 들어갈 공간이 없는 인원을 말한다.
- **Then** 한참 찾는 척하다 실패하지 않고, 빠르게 "그만한 공간이 없어요"라고 알려준다.

### UC-24 — 학과 전용처럼 반려될 만한 곳은 미리 경고한다 (우선순위 2)
- **목표**: 신청했다가 학과 전용이라 반려당하는 헛걸음을 피하고 싶다.
- **When** 추천받은 공간이 특정 학과/부서 전용이다.
- **Then** "이 공간은 ○○ 전용이라 반려될 수 있어요" 같은 경고가 추천과 함께 보인다.

### UC-25 — 공간의 주의사항을 같이 보여준다 (우선순위 2)
- **목표**: 예약 전에 "최대 몇 시간", "어떤 용도만" 같은 제약을 알고 싶다.
- **When** 추천 공간에 이용 제약/공지가 있다.
- **Then** 그 안내문이 추천과 함께 보여서, 신청 전에 알 수 있다.

### UC-26 — 너무 긴 시간 요청은 안내해준다 (우선순위 2)
- **목표**: "최대 8시간" 같은 제한을 모르고 10시간을 잡으려 했을 때 알려줬으면.
- **When** 공간 제한 시간을 넘는 길이로 요청한다.
- **Then** 제한이 있다는 걸 알려주거나 그 공간을 권하지 않는다.

### UC-27 — 찾는 도중에도 멈출 수 있다 (우선순위 2)
- **목표**: 마음이 바뀌면 탐색 중에도 중단하고 싶다.
- **Given** 찾는 중.
- **When** 취소한다.
- **Then** 탐색이 멈추고, 다시 새로 시작할 수 있다.

## 5. 신청서를 대신 채워준다 — 폼 작성 (사용자 체감)

### UC-28 — 행사 설명을 미리 말해두면 신청서가 알아서 채워진다 (우선순위 1)
- **목표**: 행사구분·단체·행사명·목적을 일일이 고르기 싫다.
- **Given** 가능한 공간을 추천받았고, 내가 앞서 "컴공 학생회 운영위원회 회의"라고 말해뒀다.
- **When** 신청서 단계로 넘어간다.
- **Then** 단체·행사명·용도·행사 종류가 내 말에서 알아서 채워진 신청서 초안이 보인다.

### UC-29 — 설명을 안 했으면 한 번만 물어본다 (우선순위 1)
- **목표**: 모르는 걸 캐묻기보다 한 방에 물어봤으면.
- **Given** 행사 설명을 한 적이 없다.
- **When** 신청서 단계로 넘어간다.
- **Then** "어떤 단체의 어떤 행사로 신청할까요?" 식으로 한 번에 물어본다. 항목마다 따로따로 캐묻지 않는다.

### UC-30 — 신청서 항목을 말로 고칠 수 있다 (우선순위 1)
- **목표**: 칸을 클릭해서 고치는 대신 말로 바꾸고 싶다.
- **Given** 신청서 초안이 떠 있다.
- **When** "행사명은 운영위원회 회의로", "주관단체는 총학생회로", "용도는 ...로" 라고 말한다.
- **Then** 해당 항목만 바뀌고, 내가 직접 칸을 누르지 않아도 된다.

### UC-31 — 행사 종류를 알아서 분류한다 (우선순위 2)
- **목표**: "행사구분"이 뭔지 고민하기 싫다.
- **When** "동아리 정기모임", "세미나", "보충수업", "학과 행사"처럼 말한다.
- **Then** 거기에 맞는 행사 종류로 알아서 분류된다 (내가 코드/분류표를 볼 필요 없다).

### UC-32 — 채워진 신청서가 내 말과 맞는지 보인다 (우선순위 1, 신뢰)
- **목표**: 제출 전에 뭐가 들어가는지 눈으로 확인하고 싶다.
- **When** 신청서 초안을 본다.
- **Then** 단체·행사명·인원·용도·날짜·시간이 또렷이 보이고, 내가 말한 것과 일치하는지 확인할 수 있다.

## 6. 내가 확인하고 제출한다 — 신뢰와 안전

### UC-33 — 내 확인 없이는 절대 제출되지 않는다 (우선순위 1, 핵심 신뢰)
- **목표**: 내가 모르는 사이에 예약이 들어가면 안 된다.
- **Given** 신청서 초안이 떠 있다.
- **When** 아직 확인 버튼을 누르지 않았다.
- **Then** 어떤 경우에도 자동으로 제출되지 않는다. 반드시 내가 마지막에 확인해야 진행된다.

### UC-34 — 확인하면 알아서 제출하고 끝났다고 알려준다 (우선순위 1)
- **목표**: 확인만 누르면 나머지는 알아서.
- **When** 추천·신청서를 확인하고 "예약" 같은 확정 버튼을 누른다.
- **Then** 진행되는 게 보이고("작성 중→저장 중" 등), 끝나면 "예약 완료"라고 분명히 알려준다.

### UC-35 — 앱을 닫아둬도 끝나면 알려준다 (우선순위 2)
- **목표**: 제출 누르고 다른 일 해도 결과를 놓치지 않길.
- **Given** 확정을 눌러 진행 중.
- **When** 사이드 패널/창을 닫고 다른 작업을 한다.
- **Then** 완료되면 알림으로 알려준다 (창을 계속 보고 있지 않아도 된다).

### UC-36 — 제출 중에는 중복으로 못 누르게 막는다 (우선순위 2)
- **목표**: 두 번 눌러 두 번 예약되면 곤란하다.
- **Given** 제출이 진행 중.
- **When** 또 입력하거나 다시 누르려 한다.
- **Then** 입력/버튼이 잠겨 중복 제출이 안 된다.

### UC-37 — 제출이 실패하면 실패라고 말해준다 (우선순위 1)
- **목표**: 됐는지 안 됐는지 애매하게 두지 않길.
- **When** 어떤 이유로든 제출이 실패한다.
- **Then** "예약에 실패했어요"라고 분명히 알려주고, 다시 시도하거나 다른 공간을 보라고 안내한다. "완료"라고 거짓으로 말하지 않는다.

### UC-38 — 미리보기로 GLS에 채워진 모습을 볼 수 있다 (우선순위 2)
- **목표**: 실제 신청 화면에 어떻게 들어가는지 보고 안심하고 싶다.
- **When** 미리보기를 요청한다.
- **Then** 실제 GLS 신청 화면에 값이 채워진 모습을 보고, 마음에 안 들면 제출하지 않고 되돌릴 수 있다.

### UC-39 — 내가 잡으려는 사이 남이 먼저 채갈 수 있다 (우선순위 2)
- **목표**: 추천받고 누르는 사이 남이 선점하면, 잘못 됐다고 알려줬으면.
- **Given** 가능하다고 추천받았다.
- **When** 확인을 누르는 사이 같은 시간대를 누가 먼저 예약했다.
- **Then** "방금 다른 사람이 예약했어요" 식으로 알려주고 다른 공간을 권한다 (잘못된 완료로 끝내지 않는다).

### UC-40 — 이미 같은 시간에 내 예약이 있으면 막아준다 (우선순위 2)
- **When** 같은 시간대에 이미 내 예약이 있는데 또 잡으려 한다.
- **Then** 중복이라고 알려준다.

## 7. 막혔을 때 — 로그인 / 중단 / 복구

### UC-41 — GLS 로그인이 안 돼 있으면 로그인하라고 안내한다 (우선순위 1)
- **목표**: 로그인 안 한 줄 모르고 헤매기 싫다.
- **Given** GLS에 로그인돼 있지 않다.
- **When** 예약을 진행한다.
- **Then** "GLS 로그인이 필요해요"라고 알려주고, 로그인할 수 있게 안내한다. 내 비밀번호를 채팅창에 입력하라고 하지 않는다.

### UC-42 — 로그인하면 알아서 하던 걸 이어간다 (우선순위 1)
- **목표**: 로그인하고 돌아오면 처음부터 다시 하기 싫다.
- **Given** 로그인하라는 안내를 받았다.
- **When** GLS에 직접 로그인하고 돌아온다.
- **Then** 멈췄던 지점부터 자동으로 이어서 진행한다 (조건을 다시 입력할 필요 없다).

### UC-43 — 도중에 로그인이 풀려도 다시 이어진다 (우선순위 1)
- **목표**: 한참 진행했는데 세션 만료로 다 날리기 싫다.
- **Given** 공간을 찾던/제출하려던 도중에 로그인이 풀렸다.
- **When** 다시 로그인한다.
- **Then** "세션이 만료됐어요" 안내 후, 다시 로그인하면 끊긴 지점부터 이어서 진행한다 (처음부터 다시 안 한다).

### UC-44 — 앱을 닫았다 열어도 하던 대화가 그대로다 (우선순위 1)
- **목표**: 실수로 닫아도 진행 상황을 잃지 않길.
- **Given** 인원·시간을 말해두고 추천까지 받은 상태.
- **When** 패널을 닫았다가 다시 연다.
- **Then** 주고받던 대화와 추천/신청서 상태가 그대로 복원돼 이어서 할 수 있다.

### UC-45 — 다른 탭/창을 보고 있어도 진행된다 (우선순위 2)
- **목표**: 예약 진행 중에 다른 일 좀 봤다고 멈추면 곤란하다.
- **Given** 예약이 진행 중.
- **When** 다른 탭을 보거나 GLS 창을 뒤로 둔다.
- **Then** 가능하면 그대로 진행하고, 정 안 되면 "GLS 창을 활성화해 주세요"라고 분명히 안내한다 (말없이 멈추지 않는다).

## 8. 예전처럼 다시 — 반복 예약 편의

- **목표**: 매주 같은 신청서를 또 채우기 싫다.
- **Given** 같은 단체·행사로 여러 번 예약한 적이 있다.
- **When** 새로 예약하다 신청서 단계에 온다.
- **Then** "지난번처럼 ○○ 행사로 채울까요?" 하고 제안한다. 단, 내 확인 없이 자동으로 넣지는 않는다.

### UC-47 — "네" 하면 그대로 채워진다 (우선순위 1)
- **Given** "지난번처럼" 제안이 떠 있다.
- **When** "네" / "좋아" / "그걸로"라고 답한다.
- **Then** 지난 신청 내용이 그대로 채워져, 거의 바로 제출 단계로 간다.

### UC-48 — "아니" 하면 새로 입력한다 (우선순위 2)
- **Given** "지난번처럼" 제안이 떠 있다.
- **When** "아니, 새로 할래"라고 한다.
- **Then** 제안을 치우고 새 행사 정보를 받는다.

### UC-49 — "저번처럼 해줘"라고 먼저 말할 수 있다 (우선순위 1)
- **목표**: 내가 먼저 재사용을 요청하고 싶다.
- **When** "저번처럼 해줘"라고 말한다.
- **Then** 지난 신청 내용을 찾아 제안하거나 채워준다.

### UC-50 — 지운 대화는 다시 추천에 안 나온다 (우선순위 2)
- **목표**: 잘못된/필요 없는 예전 예약이 자꾸 제안되면 거슬린다.
- **Given** 예전 예약 대화를 지웠다.
- **When** 다시 예약한다.
- **Then** 지운 내용은 "지난번처럼" 제안에 더 이상 등장하지 않는다.

## 9. 정기 예약 알림 — 알아서 챙겨준다

### UC-51 — 매주 하던 예약을 미리 알려준다 (우선순위 3)
- **목표**: 매주 잊지 않고 예약하던 걸 챙겨줬으면.
- **Given** 같은 요일·시간·행사로 여러 번 예약한 적이 있다.
- **When** 앱을 연다.
- **Then** "다음 ○요일도 △△ 예약하시겠어요?"라고 날짜·시간·공간·행사가 채워진 알림이 위에 뜬다.

### UC-52 — 알림에서 "예약할게요" 하면 거의 끝난다 (우선순위 3)
- **Given** 정기 예약 알림이 떠 있다.
- **When** "네, 예약할게요"를 누른다.
- **Then** 그 내용으로 곧장 예약이 시작돼, 거의 바로 확인 단계까지 간다 (조건을 다시 적을 필요 없다).

### UC-53 — "나중에" 하면 조용히 사라진다 (우선순위 3)
- **When** 알림에서 "나중에"를 누른다.
- **Then** 알림이 사라지고, 같은 알림으로 계속 귀찮게 하지 않는다.

### UC-54 — 지난 날짜 알림은 안 뜬다 (우선순위 3)
- **목표**: 이미 지난 날짜를 예약하라고 하면 황당하다.
- **When** 알림이 제안한 날짜가 이미 지났다.
- **Then** 그 알림은 사라지고, 다가오는 날짜의 알림만 보인다.

### UC-55 — 처음 쓰는 사람에겐 알림이 안 뜬다 (우선순위 3)
- **목표**: 패턴도 없는데 엉뚱한 알림이 뜨면 신뢰가 깨진다.
- **Given** 반복 예약 이력이 거의 없다.
- **When** 앱을 연다.
- **Then** 정기 예약 알림이 뜨지 않는다.

## 10. 여러 예약 관리 — 내 대화들

### UC-56 — 지난 대화 목록을 볼 수 있다 (우선순위 2)
- **목표**: 전에 뭘 예약했는지/하다 만 게 뭔지 보고 싶다.
- **When** 사용 화면을 연다.
- **Then** 최근에 주고받은 대화들이 제목·미리보기와 함께 목록으로 보인다.

### UC-57 — 새 대화 버튼만 눌렀다고 빈 대화가 쌓이지 않는다 (우선순위 2)
- **목표**: 실수로 버튼만 눌러도 쓸데없는 빈 항목이 안 생기길.
- **When** "새 대화"만 누르고 아무 말도 안 한 채 나간다.
- **Then** 목록에 빈 대화가 생기지 않는다. 첫 메시지를 보낸 순간부터 목록에 잡힌다.

### UC-58 — 지난 대화를 골라 이어서 볼 수 있다 (우선순위 2)
- **When** 목록에서 지난 대화를 고른다.
- **Then** 그때 주고받은 내용이 그대로 보여, 무슨 예약이었는지 알 수 있다.

### UC-59 — 필요 없는 대화를 지울 수 있다 (우선순위 2)
- **When** 대화를 삭제한다.
- **Then** 목록에서 사라지고 다시 나타나지 않는다.

### UC-60 — 대화 제목이 알아서 알아보기 쉽게 붙는다 (우선순위 2)
- **목표**: 목록에서 어떤 예약이었는지 한눈에 구분하고 싶다.
- **When** 예약 대화를 진행한다.
- **Then** 날짜·행사 등으로 알아보기 쉬운 제목이 자동으로 붙는다.

### UC-61 — 여러 예약을 번갈아 해도 안 섞인다 (우선순위 2)
- **목표**: A 동아리 예약과 B 행사 예약을 번갈아 해도 헷갈리지 않길.
- **When** 한 대화를 하다 다른 대화로 갔다가 다시 돌아온다.
- **Then** 각 대화의 내용·진행 상황이 서로 섞이지 않고 따로 유지된다.

## 11. 신뢰와 안전 — "믿고 맡겨도 되나?"

### UC-62 — 비밀번호를 앱에 입력하라고 하지 않는다 (우선순위 1, 보안 체감)
- **목표**: 내 학교 계정 정보를 앱에 넘기는 건 불안하다.
- **When** 예약 전 과정을 진행한다.
- **Then** GLS 아이디/비밀번호를 이 앱(채팅창)에 입력하라고 요구하지 않는다. 로그인은 내가 GLS에서 직접 한다.

### UC-63 — 내가 안 한 예약은 절대 안 들어간다 (우선순위 1)
- **목표**: 자동이라더니 멋대로 예약하면 책임 문제가 생긴다.
- **When** 어떤 흐름이든 끝까지 가본다.
- **Then** 내가 명시적으로 확인한 예약만 제출된다. 추천·제안 단계에서 임의로 신청되지 않는다.

### UC-64 — 무엇이 예약될지 항상 먼저 보여준다 (우선순위 1)
- **목표**: 깜깜이로 진행되면 불안하다.
- **When** 제출 직전.
- **Then** 어떤 공간을, 언제, 어떤 행사로 예약하는지 요약이 항상 먼저 보인다.

## 12. 오류가 사용자에게 어떻게 보이는가 — 오류 전달 품질

> 이 섹션은 "어떤 오류가 나는가"보다 **"오류가 났을 때 사용자가 무엇을 느끼고 무엇을 할 수 있는가"**를 본다.
> 각 케이스는 아래 **5가지 질문**으로 판정한다. 하나라도 "아니오"면 결함이다.
>
> 1. **드러나는가** — 조용히 실패하지 않고 사용자에게 보이는가? (단, 사용자가 몰라도 되는 건 조용히 처리해도 좋다 → UC-76)
> 2. **사람 말로 원인을** — 에러 코드·영어·기술 용어가 아니라 "왜 안 됐는지"를 사용자 말로 알려주는가?
> 3. **다음 행동 안내** — 재시도/조건 변경/로그인 등 "이제 뭘 하면 되는지" 알려주는가?
> 4. **이어서 됨** — 처음부터 다시 안 해도 되는가? (쓴 내용·진행 보존)
> 5. **결과가 분명** — 됐는지 안 됐는지 애매하게 두지 않는가?

### UC-65 — 조용히 실패하는 일이 없다 (우선순위 1, 총괄)
- **목표**: 뭐가 막혔는지도 모른 채 방치되긴 싫다.
- **Given** 어떤 단계든 막히는 상황(찾기·로그인·신청서·제출 등).
- **When** 막힘이 발생한다.
- **Then** 모든 막힘은 화면에 드러난다. 버튼이 그냥 안 먹거나, 아무 반응 없이 멈춰 있거나, 진행 표시만 계속 돌고 끝나지 않는 일이 없다.

### UC-66 — 오류 메시지가 사람 말이다 (우선순위 1)
- **목표**: 무슨 소린지 모를 영어/코드가 뜨면 더 불안하다.
- **When** 오류 안내가 뜬다.
- **Then** "다른 사람이 방금 예약했어요", "GLS 로그인이 필요해요"처럼 사람 말로 나온다. `Error 500`, `undefined`, 스택 추적, 영어 예외 메시지 같은 게 사용자에게 노출되지 않는다.

### UC-67 — 인터넷/서버가 안 되면 알려주고, 쓴 내용은 지켜준다 (우선순위 1)
- **목표**: 안 되면 안 된다고 말해주고, 적은 게 날아가지 않길.
- **Given** 인터넷이 끊겼거나 서버가 응답 없음.
- **When** 메시지를 보낸다.
- **Then** "일시적인 문제가 있어요, 다시 시도해 주세요"라고 알려준다. 내가 방금 쓴 내용은 사라지지 않고, 다시 시도할 방법(같은 메시지 재전송 등)이 있다.

### UC-68 — 응답이 안 오면 무한 대기로 두지 않는다 (우선순위 1)
- **목표**: 영원히 빙글빙글 도는 화면에 갇히기 싫다.
- **Given** 어떤 단계가 한참 응답이 없다(서버·GLS가 멈춤).
- **When** 일정 시간이 지난다.
- **Then** 무한 대기 대신 "오래 걸리고 있어요" 또는 "실패했어요, 다시 해볼까요?"로 전환된다. 사용자는 계속 기다릴지/다시 할지 정할 수 있다.

### UC-69 — 느릴 땐 처리 중임을 보여준다 (우선순위 1)
- **목표**: 멈춘 건지 느린 건지 구분되길.
- **When** 응답이 평소보다 느리다(공간 여러 곳 확인 등).
- **Then** "찾는 중", "신청서 작성 중"처럼 진행 중임이 보이고, 결국 결과가 온다.

### UC-70 — 됐는지 안 됐는지 애매하게 두지 않는다 (우선순위 1)
- **목표**: 예약이 들어간 건지 아닌지 늘 분명히 알고 싶다.
- **Given** 제출을 눌렀는데 GLS 응답이 느리거나 불확실하다.
- **When** 제출 결과를 기다린다.
- **Then** 끝에 반드시 "예약 완료" 또는 "예약 실패" 중 하나로 분명히 알려준다. "아마 된 것 같아요" 같은 모호한 상태로 끝나지 않는다.

### UC-71 — 다시 시도해도 중복 예약이 안 생긴다 (우선순위 1)
- **목표**: 실패한 줄 알고 다시 눌렀다가 두 번 예약되면 곤란하다.
- **Given** 제출이 실패했거나 결과가 불확실해 다시 시도한다.
- **When** 재시도한다.
- **Then** 같은 예약이 두 번 들어가지 않는다 (이미 됐으면 "이미 예약됐어요"라고 알려준다).

### UC-72 — 재시도가 "처음부터"가 아니다 (우선순위 1)
- **목표**: 한 번 막혔다고 조건을 다 다시 입력하기 싫다.
- **Given** 탐색·제출 등에서 한 번 실패했다.
- **When** 다시 시도한다.
- **Then** 내가 말한 조건·신청서 내용은 그대로 남아 있어, 막힌 지점부터 이어서 한다.

### UC-73 — 나를 탓하지 않고 고칠 방법을 준다 (우선순위 1)
- **목표**: "잘못 입력했습니다"만 띄우고 끝나면 답답하다.
- **Given** 내가 애매하거나 잘못 말해서 막혔다.
- **When** 오류/되묻기가 뜬다.
- **Then** 비난조가 아니라 "몇 시까지 쓰실까요?"처럼 무엇을 고치면 되는지 구체적으로 안내한다.

### UC-74 — GLS 화면이 평소와 달라도 멈춰 서서 알려준다 (우선순위 1)
- **목표**: 학교가 GLS를 바꿔도 엉뚱한 곳을 누르지 않길.
- **Given** GLS 화면 구성이 평소와 다르다(학교 측 변경).
- **When** 예약을 진행한다.
- **Then** 무작정 잘못 누르지 않고 "지금은 진행이 어려워요"라고 알려준다. 잘못된 칸에 값을 넣거나 엉뚱한 버튼을 누르는 식의 조용한 오작동이 없다.

### UC-75 — 신청서를 채우다 실패해도 어중간하게 안 들어간다 (우선순위 1)
- **목표**: 절반만 채워진 채 이상하게 제출되면 최악이다.
- **Given** 신청서를 자동으로 채우는 중 일부 항목에서 막힌다.
- **When** 작성이 실패한다.
- **Then** 반쯤 채워진 채 제출되지 않는다. "신청서 작성에 실패했어요"라고 알리고, 어중간한 상태로 GLS에 남기지 않는다(또는 남았으면 그 사실을 알려준다).

### UC-76 — 사용자가 몰라도 되는 건 조용히 알아서 처리한다 (우선순위 3, "좋은 침묵")
- **목표**: 사소한 건 나를 귀찮게 하지 말고 알아서 넘어갔으면.
- **Given** GLS에 들어가니 공지 팝업이 떠 있다(내가 신경 쓸 필요 없는 것).
- **When** 예약을 진행한다.
- **Then** 공지 팝업을 알아서 닫고 진행한다. 사용자에게 굳이 알리지 않아도 되는 건 조용히 처리한다 (모든 걸 다 알리는 게 능사는 아니다 — 단 예약 결과·막힘은 반드시 알린다).

### UC-77 — 빠르게 여러 번 보내도 꼬이지 않는다 (우선순위 1)
- **When** 메시지를 빠르게 연달아 보내거나 버튼을 연타한다.
- **Then** 답이 뒤섞이거나 화면이 깨지지 않고, 가장 최근 내용 기준으로 일관되게 답한다. 중복 동작이 일어나지 않는다.

### UC-78 — GLS가 거부하는 요청은 이유를 알려준다 (우선순위 1)
- **목표**: 왜 안 되는지 모른 채 막히면 답답하다.
- **When** "오늘 22시부터 다음날 1시까지"처럼 자정을 넘기거나, 공간 제한을 넘는 요청을 한다.
- **Then** 도중에 그냥 깨지지 않고, "그 시간대는 예약이 안 돼요" 식으로 안 되는 이유를 알려준다.
- **And** GLS가 거부 사유를 화면에 보여주면(공휴일/시험기간/신청 불가 기간 등), 그 메시지를 사람 말로 그대로 전달한다. 단, 정책을 스스로 추론해 이유를 분류하지는 않는다 (그 부분은 범위 밖).

### UC-79 — 다른 사람 예약·오류가 내게 새지 않는다 (우선순위 1, 프라이버시)
- **목표**: 내 이력은 나만 보고, 남의 것이 섞이지 않길.
- **When** 평소처럼 사용한다.
- **Then** 다른 사람의 대화·예약 이력·오류가 내 목록/추천/화면에 섞여 보이지 않는다.

## 13. 통합 여정 — 처음부터 끝까지

### UC-80 — 신규 사용자 첫 예약 완주 (우선순위 1)
- **목표**: 설치하고 처음으로, 막힘없이 예약 하나를 끝낸다.
1. 설치 후 소개를 보고 사용 화면으로 간다.
2. "다음 주 화요일 18시부터 2시간, 20명 학생회 회의실 잡아줘" 입력.
3. 로그인 안내가 뜨면 GLS에 로그인하고 돌아온다.
4. 가능한 공간을 추천받는다.
5. 내가 말한 "학생회"로 신청서가 채워진다.
6. 요약을 확인하고 확정한다.
7. "예약 완료" 알림을 받는다.
- **Then** 한 번도 "이거 왜 이래?" 하지 않고 끝까지 완주한다. 직접 GLS를 다뤘을 때보다 확실히 빠르고 편하다.

### UC-81 — 단골 사용자: 알림 한 번으로 끝 (우선순위 3)
- **목표**: 매주 하던 예약을 알림 하나로 처리한다.
1. 앱을 여니 "다음 화요일도 예약하시겠어요?" 알림이 떠 있다.
2. "네, 예약할게요"를 누른다.
3. "지난번처럼 채울까요?"에 "네"라고 한다.
4. 요약 확인 후 확정 → 완료.
- **Then** 거의 클릭 몇 번으로 끝난다. 같은 정보를 다시 타이핑하지 않는다.

### UC-82 — 중간에 끊겨도 결국 성공 (우선순위 1)
- **목표**: 세션이 풀려도 결국 예약을 끝낸다.
1. 공간을 찾던 중 로그인이 풀린다.
2. 다시 로그인한다.
3. 끊긴 지점부터 이어져 추천을 받는다.
4. 확인 후 완료.
- **Then** 중간 사고에도 처음부터 다시 하지 않고 성공한다.

### UC-83 — 안 되면 조건을 바꿔 결국 성공 (우선순위 1)
- **목표**: 처음엔 실패해도 조정해서 잡는다.
1. "내일 14시 100명" → "그만한 공간이 없어요".
2. "아니 15명으로" 정정.
3. 가능한 공간을 추천받아 완료.
- **Then** 실패가 막다른 길이 아니라, 자연스럽게 조건을 바꿔 성공으로 이어진다.

## 14. 추가 고위험 사용 시나리오 — 실제 알파테스트에서 자주 흔들릴 지점

### UC-84 — 특정 공간을 콕 집어 예약할 수 있다 (우선순위 1)
- **목표**: "아무 데나"가 아니라 내가 원하는 강의실 하나만 확인하고 싶다.
- **When** "반도체관 400126호 내일 18시부터 2시간 20명"처럼 공간을 구체적으로 말한다.
- **Then** 그 공간이 비어 있으면 그 공간을 추천한다. 다른 공간을 먼저 추천하지 않는다.

### UC-85 — 지정한 공간이 차 있으면 멋대로 다른 곳을 고르지 않는다 (우선순위 1)
- **목표**: 내가 특정 공간을 말했는데, 모르는 사이 다른 곳으로 바뀌면 안 된다.
- **Given** 내가 특정 공간을 지정했다.
- **When** 그 공간이 해당 시간에 비어 있지 않다.
- **Then** "그 공간은 어려워요. 같은 조건으로 다른 공간을 찾아볼까요?"처럼 내 동의를 구한다. 말없이 다른 공간으로 바꾸지 않는다.

### UC-86 — 건물명이 애매하면 확인 질문을 한다 (우선순위 1)
- **목표**: 비슷한 이름 때문에 엉뚱한 캠퍼스/건물로 예약되면 안 된다.
- **When** "학생회관"처럼 캠퍼스나 건물이 애매할 수 있는 표현을 쓴다.
- **Then** 앱이 확신하지 못하면 "명륜/율전 중 어디인가요?"처럼 확인한다. 추측으로 진행하지 않는다.

### UC-87 — 캠퍼스 별칭을 알아듣는다 (우선순위 1)
- **목표**: 공식 명칭을 몰라도 평소 부르는 말로 쓰고 싶다.
- **When** "율전", "자과캠", "명륜", "인사캠"처럼 별칭으로 말한다.
- **Then** 올바른 캠퍼스로 이해하거나, 애매하면 확인 질문을 한다.

### UC-88 — 30분 단위 시간을 자연스럽게 처리한다 (우선순위 1)
- **목표**: "6시 반" 같은 표현도 그대로 쓰고 싶다.
- **When** "내일 6시 반부터 8시까지 12명"이라고 말한다.
- **Then** 18:30~20:00으로 이해해 진행한다.

### UC-89 — 지원하지 않는 분 단위는 바로잡아준다 (우선순위 1)
- **목표**: 학교 예약 시간이 10분 단위가 아니라면 미리 알려줬으면.
- **When** "18시 10분부터 19시 40분까지"처럼 애매한 분 단위를 말한다.
- **Then** 가능한 예약 단위에 맞춰 다시 물어본다. 임의로 시간을 반올림해서 진행하지 않는다.

### UC-90 — 너무 이른/늦은 시간은 헛진행하지 않는다 (우선순위 1)
- **When** "새벽 3시부터 5시까지" 또는 "밤 11시부터"처럼 일반 예약 시간 밖으로 보이는 시간을 말한다.
- **Then** 그 시간대 예약이 가능한지 확인하고, 안 되면 이유를 알려준다. 무작정 공간 탐색으로 넘어가지 않는다.

### UC-91 — 오늘 이미 지난 시간은 예약하려 하지 않는다 (우선순위 1)
- **목표**: 실수로 이미 지난 시간을 말했을 때 잡히면 안 된다.
- **Given** 현재 시간이 오후 5시다.
- **When** "오늘 오후 2시에 10명"이라고 말한다.
- **Then** 이미 지난 시간이라고 알려주고, 날짜나 시간을 다시 받는다.

### UC-92 — 너무 먼 날짜는 정직하게 안내한다 (우선순위 3) [Graceful Decline]
- **When** "내년 12월 31일 18시"처럼 GLS에서 아직 열리지 않았을 수 있는 날짜를 말한다.
- **Then** 그대로 진행하다 깨지지 않고, "아직 신청할 수 없는 날짜일 수 있어요 / GLS에서 진행이 안 돼요"라고 안내하고 날짜를 다시 받는다. (신청 가능 기간을 정확히 추론해 알려주는 건 범위 밖.)

### UC-93 — 최소 인원 조건에 맞지 않는 큰 공간을 권하지 않는다 (우선순위 1)
- **목표**: 2명 모임인데 40명 이상 공간을 추천받아 반려될 위험을 피하고 싶다.
- **When** "2명 회의실"처럼 아주 적은 인원을 말한다.
- **Then** 최소 인원 조건에 맞지 않는 공간은 피하거나, 그 공간이 왜 부적절할 수 있는지 알려준다.

### UC-94 — 강한 조건에서 실패하면 조건을 넓힐지 물어본다 (우선순위 1)
- **목표**: 지정한 건물에는 없어도 근처 다른 곳을 찾고 싶을 수 있다.
- **Given** 특정 건물/공간으로 요청했다.
- **When** 그 범위 안에서 가능한 공간이 없다.
- **Then** "이 건물에는 없어요. 같은 캠퍼스 전체로 넓혀볼까요?"처럼 다음 선택지를 준다.

### UC-95 — 지원하지 않는 시설 조건은 정직하게 안내한다 (우선순위 3) [Graceful Decline]
- **목표**: 빔프로젝터/화이트보드 같은 조건을 말했는데 조용히 무시되면 곤란하다.
- **When** "빔프로젝터 있는 곳", "화이트보드 있는 곳"처럼 시설 조건을 붙인다.
- **Then** "그 시설 조건은 아직 확인이 어려워요"라고 분명히 말한다. 조건을 조용히 무시한 채 평범한 공간을 추천하지 않는다. (시설 필터는 범위 밖 — D-022.)

### UC-96 — 추천 이후 조건을 바꾸면 다시 찾아준다 (우선순위 1)
- **목표**: 추천을 받았는데 시간이 바뀌면, 예전 추천으로 제출되면 안 된다.
- **Given** 추천 공간이 떠 있다.
- **When** "아 시간은 7시부터로 바꿔줘"라고 말한다.
- **Then** 기존 추천을 그대로 제출하지 않고, 바뀐 시간 기준으로 다시 확인한다.

### UC-97 — "다른 곳" 이후 최종 요약은 최신 공간을 보여준다 (우선순위 1)
- **목표**: 첫 번째 추천을 거절했는데 제출 요약에 첫 공간이 남아 있으면 안 된다.
- **Given** 첫 추천을 받고 "다른 곳 보여줘"를 눌러 두 번째 공간을 받았다.
- **When** 제출 직전 요약을 본다.
- **Then** 요약에는 두 번째로 선택한 공간만 보인다. 이전 후보 이름이 섞이지 않는다.

### UC-98 — 신청서 필수 정보가 부족하면 제출 버튼이 막힌다 (우선순위 1)
- **목표**: 빈 칸이 있는 신청서가 제출되어 실패하는 걸 피하고 싶다.
- **Given** 신청서 초안에 단체명이나 사용목적 등 필수 내용이 빠져 있다.
- **When** 제출하려 한다.
- **Then** 어떤 내용이 부족한지 알려주고, 보완하기 전에는 제출되지 않는다.

### UC-99 — 사용자가 GLS 화면을 직접 건드려도 안전하게 멈춘다 (우선순위 1)
- **목표**: 앱이 채우는 중에 내가 실수로 GLS 화면을 누르면 이상한 예약이 되지 않길.
- **Given** 앱이 GLS 신청 화면을 자동으로 채우는 중이다.
- **When** 사용자가 직접 다른 건물/시간을 클릭하거나 화면을 닫는다.
- **Then** 앱이 변경을 감지하면 멈추고 확인을 요청한다. 사용자가 바꾼 값과 앱이 생각한 값이 섞여 제출되지 않는다.

### UC-100 — GLS 탭을 닫아도 상황을 알려준다 (우선순위 1)
- **Given** 공간을 찾거나 제출하는 중이다.
- **When** 사용자가 GLS 탭을 닫는다.
- **Then** 앱이 "GLS 창이 닫혔어요"라고 알려주고, 다시 열어 이어갈지 묻는다. 조용히 실패하지 않는다.

### UC-101 — 이미 GLS에서 작성 중인 신청서를 덮어쓰지 않는다 (우선순위 1)
- **목표**: 내가 GLS에서 직접 작성하던 내용이 앱 때문에 사라지면 안 된다.
- **Given** GLS 신청 화면에 사용자가 직접 입력해둔 내용이 있다.
- **When** 앱으로 새 예약을 진행한다.
- **Then** 기존 작성 중인 내용이 있으면 덮어쓰기 전에 확인한다.

### UC-102 — 학교 화면의 공간 목록이 바뀌어도 한 공간 때문에 전체가 실패하지 않는다 (우선순위 1)
- **목표**: 어떤 공간이 사라졌거나 이름이 바뀌어도 앱이 완전히 망가지지 않았으면.
- **When** 추천 후보 중 하나가 GLS 화면에서 더 이상 보이지 않는다.
- **Then** 그 후보는 건너뛰거나 사용자에게 알려주고 다음 후보를 확인한다. 전체 예약 흐름이 이유 없이 중단되지 않는다.

### UC-103 — 알림 권한이 없어도 결과를 확인할 수 있다 (우선순위 3)
- **목표**: 브라우저 알림을 꺼둔 사람도 예약 결과를 놓치지 않길.
- **Given** 브라우저 알림이 꺼져 있다.
- **When** 제출 후 앱을 닫았다가 다시 연다.
- **Then** 알림이 뜨지 않았더라도 앱 안에서 완료/실패 결과를 확인할 수 있다.

### UC-104 — 브라우저를 새로 켜도 최근 진행 상태가 이해된다 (우선순위 1)
- **목표**: 컴퓨터가 꺼졌거나 브라우저가 종료돼도 내가 어디까지 했는지 알고 싶다.
- **Given** 예약을 진행하다 브라우저를 종료했다.
- **When** 다시 브라우저를 열고 앱을 연다.
- **Then** 이전 대화가 보이고, 이미 완료됐는지/중단됐는지/다시 시작해야 하는지 분명히 알 수 있다.

### UC-105 — 같은 말을 여러 방식으로 답해도 제안을 수락한다 (우선순위 1)
- **목표**: 꼭 "네"라고만 해야 하는 건 불편하다.
- **Given** "지난번처럼 채울까요?" 또는 "다른 공간을 찾아볼까요?" 같은 제안이 떠 있다.
- **When** "응", "그래", "좋아", "그걸로 해줘"처럼 답한다.
- **Then** 사용자가 수락했다는 뜻으로 이해하고 다음 단계로 진행한다.

### UC-106 — "아니" 뒤에 새 조건을 바로 말할 수 있다 (우선순위 1)
- **목표**: 거절하고 새 내용을 다시 따로 입력하기 귀찮다.
- **Given** 어떤 제안이 떠 있다.
- **When** "아니, 30명으로 7시에 다시 찾아줘"처럼 거절과 새 조건을 한 번에 말한다.
- **Then** 제안을 취소하고 새 조건으로 다시 진행한다.

## 15. 사용자가 반드시 시도하는 것 — 추가 시나리오

### UC-107 — 내가 한 말이 어떻게 이해됐는지 보여준다 (우선순위 1, 신뢰)
- **목표**: 날짜·시간을 잘못 알아들었으면 찾기 전에 알아채고 싶다.
- **When** "다음 주 화요일 18시 2시간 20명"이라고 말한다.
- **Then** 찾기 시작하기 전에 "5/19(화) 18:00~20:00, 20명" 식으로 **앱이 이해한 값**을 사람이 읽을 수 있게 보여준다. 내가 말한 것과 다르면 바로 잡을 수 있다 (조용히 엉뚱한 날짜로 진행하지 않는다).

### UC-108 — 이미 한 예약을 취소/변경하려 하면 정직하게 안내한다 (우선순위 1) [Graceful Decline]
- **목표**: 잘못 예약했으면 취소하거나 바꾸고 싶다.
- **Given** 예약을 이미 완료했다.
- **When** "방금 예약 취소해줘" 또는 "시간 좀 바꿔줘"라고 말한다.
- **Then** "이 앱에서는 취소·변경이 안 돼요. GLS에서 직접 하셔야 해요"라고 **정직하게** 안내한다. 되는 척하고 아무 일도 안 하지 않는다. (제출된 예약의 자동 취소·변경은 명시적 범위 밖.)

### UC-109 — 한 예약을 끝낸 뒤 같은 창에서 새 예약을 시작한다 (우선순위 1)
- **목표**: 연달아 여러 건 예약할 때 앞 예약 정보가 남으면 안 된다.
- **Given** 한 예약을 막 완료했다.
- **When** 같은 대화창에 "이번엔 금요일 14시 회의실"이라고 새로 말한다.
- **Then** 앞 예약의 날짜·인원·신청서 내용이 섞이지 않고 새 예약으로 깨끗이 시작된다 (또는 새 대화로 안내한다).

### UC-110 — 채우다 말고 다른 요청으로 바꿔도 따라온다 (우선순위 1)
- **목표**: 입력 도중 마음이 바뀌어도 처음부터 다시 하기 싫다.
- **Given** 인원만 답한 채 날짜를 묻고 있는 중.
- **When** "아 잠깐, 그냥 내일 말고 다음 주로 다시 할게"처럼 도중에 방향을 튼다.
- **Then** 앞서 답한 내용을 적절히 살리거나 정리하고, 바뀐 요청을 따라온다. 엉뚱한 옛 답과 섞지 않는다.

### UC-111 — 오전/오후가 빠진 시간은 짚고 넘어간다 (우선순위 1)
- **목표**: "3시"만 말했을 때 새벽 3시로 잡히면 안 된다.
- **When** "내일 3시에 10명"처럼 오전/오후 없이 말한다.
- **Then** 상식적인 시간(오후)으로 이해하되 확인하거나, 애매하면 "오후 3시 맞나요?"라고 묻는다. 조용히 새벽 3시로 진행하지 않는다.

### UC-112 — 예약 끝난 뒤 어디서 확인하는지 알려준다 (우선순위 3)
- **목표**: 예약이 진짜 들어갔는지 GLS에서 확인하고 싶다.
- **Given** 예약을 완료했다.
- **When** "이거 어디서 확인해?" 또는 완료 직후.
- **Then** GLS 어디에서 내 신청 내역을 볼 수 있는지(또는 승인서 출력 등) 간단히 안내한다.

### UC-113 — 여러 날짜·반복 예약 요청은 범위를 분명히 한다 (우선순위 3) [Graceful Decline · → Phase 4 기능 후보]
- **목표**: "이번 달 매주 화요일"을 한 번에 잡고 싶다.
- **When** "다음 달까지 매주 화요일 18시 회의실"처럼 여러 건을 한 번에 요청한다.
- **Then** "한 번에 하나씩 도와드려요. 가장 가까운 화요일부터 할까요?"라고 분명히 안내한다. 요청을 조용히 한 건으로 줄여버리지 않는다. (일괄 반복 예약은 Phase 4 — 지금은 거절만 검증.)

### UC-114 — 외국어로 말해도 막히지 않는다 (우선순위 3) [Graceful Decline]
- **목표**: 유학생도 쓸 수 있어야 한다.
- **When** "book a room tomorrow 3pm for 10 people"처럼 영어로 말한다.
- **Then** 무반응으로 멈추지 않고, "한국어로 말씀해 주세요" 식으로 분명히 안내한다. (다국어 예약 지원은 범위 밖 — 안 깨지고 안내하는지만 검증.)

## 16. 마지막 확인에서 갈리는 신뢰 — 신청 결과와 폼 세부

### UC-115 — "신청 완료"와 "승인 완료"를 구분한다 (우선순위 1)
- **목표**: 공간 사용이 확정된 줄 알고 갔다가 낭패를 보면 안 된다.
- **When** GLS 제출이 성공한다.
- **Then** "예약 신청이 완료됐어요"처럼 신청 완료임을 정확히 말하고, 학교 승인/반려 확인이 따로 필요하다면 그 점을 알려준다. 승인까지 끝난 것처럼 말하지 않는다.

### UC-116 — 너무 긴 행사명/목적은 제출 전에 줄이라고 알려준다 (우선순위 1)
- **목표**: 길게 쓴 설명 때문에 GLS 저장 단계에서 실패하지 않길.
- **When** 행사명이나 사용목적을 매우 길게 입력한다.
- **Then** 길이 제한이 있으면 제출 전에 알려주고 줄이게 한다. 잘려서 들어가거나 저장 실패 후에야 알게 하지 않는다.

### UC-117 — 행사 종류가 애매하면 확신하는 척하지 않는다 (우선순위 1)
- **목표**: 행사구분이 잘못 들어가 반려되는 일을 피하고 싶다.
- **When** "모임", "행사", "활동"처럼 행사 종류를 판단하기 애매하게 말한다.
- **Then** 앱이 확신하지 못하면 "정기모임/세미나/행사 중 무엇에 가까운가요?"처럼 확인한다. 임의로 분류해 제출하지 않는다.

### UC-118 — GLS에 기본 연락처가 비어 있으면 제출 전에 알려준다 (우선순위 1)
- **목표**: 내가 말한 정보는 다 줬는데 학교 계정 기본 정보 때문에 실패하면 당황스럽다.
- **Given** GLS 신청 화면의 연락처 등 기본 필수 정보가 비어 있다.
- **When** 제출하려 한다.
- **Then** 어떤 기본 정보가 비어 있는지 알려주고, GLS에서 먼저 채우도록 안내한다. 빈 연락처로 제출을 시도하지 않는다.

### UC-120 — 제출 직전에도 취소할 수 있다 (우선순위 1)
- **목표**: 요약을 보고 마음이 바뀌면 멈출 수 있어야 안심된다.
- **Given** 제출 직전 요약이 떠 있다.
- **When** "아니, 취소할게" 또는 닫기/뒤로가기를 선택한다.
- **Then** 제출이 일어나지 않고, 진행이 멈춘다. 이후 새 예약을 시작할 수 있다.

## 17. 숨은 정합성·환경 — 놓치기 쉬운 시나리오

### UC-121 — 추천이 오래되면 제출 직전에 다시 확인한다 (우선순위 1, 정합성)
- **목표**: 추천받고 한참 뒤에 확정해도, 그새 찬 공간이 들어가면 안 된다.
- **Given** 가능하다고 추천받은 뒤 시간이 꽤 흘렀다(딴 일을 하다 돌아옴).
- **When** 뒤늦게 확정을 누른다.
- **Then** 예전 추천을 그대로 밀어붙이지 않고, 제출 직전 다시 비어 있는지 확인한다. 그새 찼으면 알려주고 다른 공간/시간을 권한다.

### UC-122 — 보던 탭을 GLS로 바꾸기 전에 물어본다 (우선순위 1)
- **목표**: 내가 작업하던 화면이 예고 없이 GLS로 바뀌어 작업이 날아가면 안 된다.
- **Given** 다른 사이트(문서 작성 등)를 보고 있는 탭이 떠 있다.
- **When** 예약을 시작해 앱이 GLS 화면을 필요로 한다.
- **Then** 보던 탭을 멋대로 GLS로 바꾸지 않고, "GLS를 새 탭/이 탭에서 열까요?"처럼 먼저 묻거나 새 탭으로 연다.

### UC-123 — GLS 점검/장애 페이지를 알아채고 알려준다 (우선순위 1)
- **목표**: 학교 시스템 점검 중인 걸 모르고 헤매기 싫다.
- **Given** GLS가 점검 중이거나 접속이 안 되는 상태다.
- **When** 예약을 진행한다.
- **Then** "지금 GLS가 점검/접속 불가 상태예요"라고 알려주고, 나중에 다시 시도하라고 안내한다. 빈 화면에서 무한정 기다리게 하지 않는다.

### UC-124 — 원하는 방이 그 시간에 차 있으면 분명히 알려준다 (우선순위 1) [Graceful Decline · → Phase 4 기능 후보]
- **목표**: 그 방을 꼭 쓰고 싶었는데 차 있으면, 적어도 분명히 알고 싶다.
- **Given** 특정 공간을 지정했는데 요청 시간에 차 있다.
- **When** "그럼 그 방 언제 비어?"라고 묻거나, 그 공간이 불가한 상황이다.
- **Then** "그 시간엔 차 있어요. 다른 시간/공간으로 다시 요청해 주세요"라고 분명히 알려준다. 빈 시간대를 자동으로 스캔해 제안하지는 않으며, 조용히 다른 방으로 바꾸지도 않는다. (빈 시간 탐색·대안 제시는 Phase 4.)

## 18. 입력·화면·기록 — 실제 사용 환경에서 생기는 마찰

### UC-127 — 한글 입력 중 Enter가 메시지를 먼저 보내지 않는다 (우선순위 1)
- **목표**: 한글 조합 중에 실수로 메시지가 끊겨 보내지면 답답하다.
- **When** 한글 입력기로 "다음 주 화요일"을 입력하며 조합 확정용 Enter를 누른다.
- **Then** 조합 중인 글자가 먼저 확정되고, 메시지가 중간에 전송되지 않는다. 내가 진짜 전송하려고 Enter를 눌렀을 때만 보내진다.

### UC-128 — 긴 문장을 붙여넣어도 화면이 깨지지 않는다 (우선순위 1)
- **목표**: 행사 설명을 복사해 붙여넣어도 앱이 버텨줬으면.
- **When** 여러 줄짜리 긴 행사 목적/공지 문구를 채팅창에 붙여넣는다.
- **Then** 앱 화면이 옆으로 밀리거나 버튼이 사라지지 않는다. 너무 길면 줄이라고 알려주되, 입력한 내용이 갑자기 사라지지 않는다.

### UC-129 — 좁은 사이드패널에서도 핵심 버튼이 보인다 (우선순위 1)
- **목표**: 노트북 화면이 좁아도 제출/취소 버튼을 놓치면 안 된다.
- **When** 사이드패널 폭이 좁거나 브라우저 창이 작다.
- **Then** 추천 공간, 신청서 요약, 제출/취소 버튼을 스크롤해서 모두 볼 수 있다. 버튼이나 긴 텍스트가 겹쳐 눌리지 않는 일이 없다.

### UC-130 — 진행 중인 대화를 삭제하면 자동화도 멈춘다 (우선순위 1)
- **목표**: 대화를 지웠는데 뒤에서 계속 예약이 진행되면 무섭다.
- **Given** 공간 탐색 또는 제출 전 단계가 진행 중이다.
- **When** 사용자가 해당 대화를 삭제한다.
- **Then** 그 대화의 진행이 멈추고, 삭제한 예약이 뒤에서 계속 제출되지 않는다. 필요하면 "진행 중인 예약도 중단돼요"라고 확인한다.

### UC-131 — 공용 PC에서 내 기록을 숨길 수 있다 (우선순위 1)
- **목표**: 동아리방/학생회실 공용 컴퓨터에서 내 예약 이력이 남는 게 불편하다.
- **Given** 대화 목록에 내 단체명·행사명이 남아 있다.
- **When** 사용자가 대화를 삭제하거나 기록을 정리한다.
- **Then** 목록과 추천에서 해당 내용이 사라진다. 다음 사용자가 내 단체명·행사명을 쉽게 볼 수 없어야 한다.

### UC-132 — 새로고침/확장 업데이트 뒤에도 버튼이 죽지 않는다 (우선순위 1)
- **목표**: 개발 중이든 업데이트 뒤든, 화면만 보이고 버튼이 안 먹는 상태는 피하고 싶다.
- **Given** 앱 화면을 열어둔 상태에서 새로고침되거나 확장이 업데이트됐다.
- **When** 다시 메시지를 보내거나 대화 목록을 연다.
- **Then** 앱이 정상적으로 다시 연결되거나, 새로 열어 달라고 안내한다. 버튼이 눌리는데 아무 반응 없는 상태로 남지 않는다.

## 부록 B. 알파테스터용 한 줄 점검 (체크리스트)
실제 테스터가 빠르게 훑을 수 있는 질문들. 모두 "그렇다"여야 한다.
- [ ] 처음 열었을 때 뭐 하는 앱인지 알았다
- [ ] 말로 적었더니 알아들었다
- [ ] 부족한 건 한 번씩만 물어봤다
- [ ] 가능한 공간을 보여줬고, 실제로 비어 있었다
- [ ] 학과 전용 등 위험은 미리 알려줬다
- [ ] 신청서를 대신 채워줬고, 내가 고칠 수 있었다
- [ ] 제출 전에 뭐가 들어갈지 보여줬다
- [ ] 내가 확인하기 전엔 예약이 안 들어갔다
- [ ] 찾기 전에 "내가 말한 날짜·시간을 이렇게 이해했다"를 보여줬다 (조용한 오역 없음)
- [ ] 끝나면 완료라고 알려줬다 (실패면 실패라고 — 애매하지 않았다)
- [ ] 오류가 떴을 때 무슨 소린지 알았다 (영어/코드가 아니라 사람 말)
- [ ] 막혔을 때 뭘 해야 할지 알려줬다 (그냥 멈추거나 무한 로딩 아니었다)
- [ ] 다시 시도할 때 처음부터 다시 안 해도 됐다 / 중복 예약이 안 생겼다
- [ ] 특정 공간/건물을 지정했을 때, 안 되면 멋대로 바꾸지 않고 물어봤다
- [ ] 추천 후 조건을 바꾸면 예전 추천이 아니라 새 조건으로 다시 확인했다
- [ ] GLS 탭을 닫거나 건드려도 조용히 실패하지 않았다
- [ ] "신청 완료"와 "승인 완료"를 헷갈리게 말하지 않았다
- [ ] 제출 직전에도 취소할 수 있었다
- [ ] 한글 입력 중 메시지가 중간에 전송되지 않았다
- [ ] 좁은 화면에서도 제출/취소 버튼이 가려지지 않았다
- [ ] 진행 중인 대화를 삭제하면 뒤에서 계속 예약되지 않았다
- [ ] 비밀번호를 이 앱에 넣으라고 하지 않았다
- [ ] 직접 GLS로 하는 것보다 빠르고 편했다
- [ ] 다음에도 쓰고 싶다

## 부록 C. 테스트할 때 준비하면 좋은 상황
- 로그인 된 상태 / 안 된 상태 둘 다
- 진행 중 로그아웃(세션 만료) 만들어보기
- 인원: 아주 적게(2명)·중간(20명)·아주 많게(500명)
- 같은 단체·요일·시간으로 3번 이상 예약해두고 → 정기 알림/“지난번처럼” 확인
- 일부러 애매하게/오타로/잡담으로 말 걸어보기
- 예약 도중 앱 닫았다 열기, 다른 탭 보기
- 인터넷 끊고 시도해보기
- 특정 건물/공간을 콕 집어 요청한 뒤, 안 될 때 범위를 넓혀보기
- 18:30 같은 30분 단위와 18:10 같은 애매한 분 단위를 모두 시도해보기
- 추천을 받은 뒤 시간/인원/공간 조건을 바꿔보기
- GLS 탭을 닫거나 직접 건드려보기
- 브라우저 알림을 꺼둔 상태로 완료 결과 확인해보기
- 예약을 끝낸 직후 같은 창에서 바로 다음 예약을 시작해보기
- 이미 완료한 예약을 "취소/변경"해달라고 말해보기
- 추천받은 뒤 일부러 한참(5~10분) 두었다가 확정 눌러보기 (그새 찼는지 재확인하는지)
- 다른 사이트를 보던 탭에서 예약을 시작해보기 (그 탭을 멋대로 GLS로 바꾸는지)
- "3시"처럼 오전/오후 없이, "book a room tomorrow"처럼 영어로도 말해보기
- "매주 화요일"처럼 여러 건을 한 번에 요청해보기
- 행사명/사용목적을 아주 길게 써보기
- 제출 직전 요약에서 취소해보기
- 완료 문구가 "승인"이 아니라 "신청" 기준으로 정확한지 확인해보기
- 한글 조합 중 Enter를 눌러보기
- 브라우저/사이드패널 폭을 좁게 줄여보기
- 진행 중인 대화를 삭제해보기
- 여러 줄짜리 긴 행사 설명을 붙여넣어보기
