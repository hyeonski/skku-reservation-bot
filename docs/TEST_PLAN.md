# SKKU 공간예약 에이전트 — 알파테스트 플랜

> 최종 수정: 2026-05-26
> 범위: P1 핵심 파이프라인 + P2 추천 강화 + P3 패턴 리마인드 + 엣지케이스
> 이번 라운드 목표: 실제 GLS 최종 제출 전까지 신뢰 가능한 예약 보조 봇으로 알파 안정화

---

## 1. 테스트 개요

### 목적
학생회·동아리 실사용 알파테스트 전, P1~P3 구현 범위의 기능과 엣지케이스를 수동으로 검증하여 치명적 버그를 사전에 제거한다.

이번 QA 라운드의 완료 기준은 "예약 자동 제출 완료"가 아니라 "사용자가 최종 제출 버튼을 누르기 직전까지 자연어 예약 보조 경험을 안정적으로 제공"하는 것이다. 따라서 최종 GLS 저장/제출 이후 결과 감지는 전체 테스트 플랜에는 남기되, 이번 라운드에서는 명시적으로 보류한다.

### 이번 라운드 우선순위

| 우선순위 | 의미 | 이번 라운드 종료 기준 |
|---|---|---|
| **Alpha Must Pass** | 알파 사용자에게 반드시 안정적으로 제공되어야 하는 기능 | 실패 시 알파테스트 보류 또는 즉시 수정 |
| **Alpha Should Pass** | 알파 품질을 높이는 중요 기능 | 실패 시 known issue로 문서화하고 우회 가능해야 함 |
| **Deferred** | 안전·환경·데이터 조건상 이번 라운드에서 보류 | 테스트 플랜에는 유지하되 실행하지 않거나 별도 controlled run으로 분리 |

### 알파 안정화 범위

#### Alpha Must Pass
- P1 자연어 입력 → 슬롯 파싱 → GLS 후보 검증 → 추천 → 신청서 초안 생성 → 초안 수정
- 건물/캠퍼스/인원/시간/날짜 필터가 실제 추천·검증 대상에 반영
- "2공학관에서 찾아줘"처럼 자연어 건물 지정 시 해당 건물 내부 공간을 대상으로 가용성 판정 및 예약 준비 진행
- 최종 제출 전까지 GLS 모달·사이드패널 상태가 일관되고, 사용자가 직접 확인 가능
- 서버 미기동, GLS 로그인 만료, 후보 없음, 조건 변경 retry에서 사용자가 복구 가능
- 사이드패널 닫기/재오픈 후 진행 중 대화와 카드 상태 복원
- X-Client-Id 소유권, XSS/SQL-like 입력, GLS 인증정보 비저장 등 기본 보안

#### Alpha Should Pass
- P2 추천 카드 생성, 수락, 거절, 수락 후 일부 수정
- P3 리마인더 표시, 수락, dismiss, dismiss 후 재노출 방지
- 온보딩, 세션 목록 정렬, 세션 삭제 UI, 상대시간 표시
- 긴 입력, 빠른 연타, 사이드패널 폭 변경 등 UX 엣지케이스

#### Deferred
- 실제 GLS 최종 저장/제출 클릭 및 예약 완료 확인
- 저장 후 notification 및 제출 성공/실패 감지
- 브라우저 완전 재시작, 확장 재설치, storage clear 기반 destructive 테스트
- DB 장애, LLM 키 만료, GLS selector break 등 강제 fault injection
- P2 추천 품질 대량 평가, P3 장기 패턴 정밀 평가
- 성능 정량 측정

### 테스트 환경
- Chrome 최신 안정 버전 (사이드패널 지원 Chrome 114+)
- GLS 포털: `kingoinfo.skku.edu` (실제 계정 로그인)
- 서버: 배포 인스턴스 또는 `localhost:8000`
- DB: Space 테이블 시딩 완료 (자연/명륜 양 캠퍼스)

### 사전 조건 체크리스트
- [ ] 서버 `GET /health` → `{ ok: true }`
- [ ] 확장 `pnpm build` → `dist/` 에러 없음
- [ ] 크롬에 확장 로드 완료, "오류" 항목 없음
- [ ] Space 테이블에 양 캠퍼스 데이터 존재
- [ ] GLS 계정 로그인 가능 (학교 VPN 불필요 확인)
- [ ] LLM API 키 유효 (DeepSeek 또는 호환 엔드포인트)
- [ ] P2 검증용: 동일 단체/행사로 완료된 대화 3건 이상
- [ ] P3 검증용: 같은 요일+시간+단체+행사 3주 연속 완료 이력

### 심각도 분류

| 등급 | 정의 | 예시 |
|---|---|---|
| **P0 — Blocker** | 핵심 흐름 불가 또는 데이터 무결성 위반 | 사용자 확인 없이 제출, 타인 대화 접근, 서버 크래시 |
| **P1 — Critical** | 핵심 흐름은 되지만 데이터 오류/기능 누락 | 잘못된 공간 예약, 슬롯 파싱 오류, 세션 복원 실패 |
| **P2 — Major** | 기능 제한 또는 UX 심각 저하 | 카드 렌더링 깨짐, 힌트 칩 미동작 |
| **P3 — Minor** | 불편하지만 우회 가능 | 오타, 미세 정렬, 불필요한 로딩 지연 |

### 제출 안전 원칙

- 이번 라운드의 예약 플로우 테스트에서는 사이드패널의 `GLS 제출`, `제출` 버튼과 GLS 모달의 `저장` 버튼을 클릭하지 않는다.
- 예약 플로우 날짜는 테스트 실행일 기준 최소 1주일 이후로 선택한다.
- GLS 모달을 닫을 때는 저장 버튼이 아니라 상단 닫기 버튼을 사용한다.
- 제출 관련 TC는 "버튼 노출, 폼 값 채움, submit 직전 상태"까지만 확인하고 실제 저장 이후 검증은 Deferred로 기록한다.

## 2. 인프라 및 설치 (6건)

> 우선순위: TC-INFRA-01~06 모두 **Alpha Must Pass**.

### TC-INFRA-01: 서버 기동 및 헬스체크
- **절차**: `cd server && pnpm dev` → `curl localhost:8000/health`
- **기대**: `{ ok: true }`, 서버 로그에 에러 없음, DB 연결 성공

### TC-INFRA-02: 확장 빌드 및 로드
- **절차**: `cd extension && pnpm build` → `chrome://extensions` → 개발자 모드 → `dist/` 로드
- **기대**: 에러 없이 확장 등록, 툴바에 아이콘 표시, 확장 상세에 "오류" 없음

### TC-INFRA-03: 사이드패널 진입
- **절차**: 확장 아이콘 클릭
- **기대**: 브라우저 우측에 사이드패널 열림 (popup이 아닌 side panel)

### TC-INFRA-04: 서버 미기동 시 확장 동작
- **절차**: 서버 미실행 상태에서 사이드패널 열고 메시지 전송
- **기대**: 적절한 에러 메시지 표시 ("서버에 연결할 수 없습니다" 등), 크래시 없음

### TC-INFRA-05: 타입체크 통과
- **절차**: `cd server && pnpm exec tsc --noEmit` / `cd extension && pnpm exec tsc --noEmit`
- **기대**: 에러 0건

### TC-INFRA-06: Prisma 마이그레이션 상태
- **절차**: `cd server && pnpm prisma migrate status`
- **기대**: 모든 마이그레이션 적용 완료

## 3. 온보딩 (7건)

> 우선순위: **Alpha Should Pass**. 단, storage clear/확장 재설치가 필요한 destructive 검증은 이번 라운드에서 보류 가능.

### TC-ONBOARD-01: 최초 설치 시 온보딩 표시
- **사전**: `chrome.storage.local`에 `onboardingComplete` 없는 상태 (확장 재설치 또는 스토리지 클리어)
- **절차**: 사이드패널 열기
- **기대**: 온보딩 스텝 0 (환영 화면) — SKKU 로고 + "공간예약, 채팅 한 번이면 끝나요"

### TC-ONBOARD-02: 스텝 전이 (0 → 1)
- **절차**: 스텝 0에서 [다음] 클릭
- **기대**: 스텝 1 (사용 예시) — "이렇게 말해보세요" + 예시 카드 4개, 점 인디케이터 변경, [←] 표시

### TC-ONBOARD-03: 스텝 뒤로가기 (1 → 0)
- **절차**: 스텝 1에서 [←] 클릭
- **기대**: 스텝 0으로 복귀

### TC-ONBOARD-04: 건너뛰기
- **절차**: 스텝 0 또는 1에서 [건너뛰기] 클릭
- **기대**: 온보딩 종료 → 세션 목록 화면, `onboardingComplete` flag 저장

### TC-ONBOARD-05: 시작하기
- **절차**: 스텝 1에서 [시작하기] 클릭
- **기대**: 세션 목록 화면 진입

### TC-ONBOARD-06: 재진입 시 온보딩 미표시
- **사전**: 온보딩 1회 완료
- **절차**: 사이드패널 닫았다가 재오픈
- **기대**: 바로 세션 목록, 온보딩 미노출

### TC-ONBOARD-07: 확장 reload 후에도 온보딩 미재표시
- **사전**: 온보딩 완료
- **절차**: `chrome://extensions`에서 확장 reload → 사이드패널 열기
- **기대**: 온보딩 미노출 (`chrome.storage.local` 영속)

## 4. 세션 목록 (12건)

> 우선순위: TC-SESSION-02, 04, 05, 06, 08, 10은 **Alpha Must Pass**. TC-SESSION-07 UI 삭제는 실제 프로필에서 destructive하면 API 검증으로 대체 가능. 나머지는 **Alpha Should Pass**.

### TC-SESSION-01: 빈 세션 목록
- **사전**: 대화 이력 없는 새 클라이언트
- **기대**: 빈 목록 안내 또는 새 대화 유도 UI

### TC-SESSION-02: 세션 목록 로딩 및 정렬
- **사전**: 완료/진행 중/중단 대화 각각 존재
- **절차**: 세션 목록 진입
- **기대**: `GET /conversations` 호출, 최대 10개 최신순, 각 항목에 status dot + 제목 + 상대시간 + 프리뷰

### TC-SESSION-03: 세션 상태별 dot 표시
- **확인**: `completed` → 초록, `active` → 파랑 + pulse, `abandoned_*` → 회색

### TC-SESSION-04: 세션 클릭 → 채팅 복원
- **절차**: 세션 목록에서 기존 대화 클릭
- **기대**: 채팅 화면 진입, 이전 메시지·phase·카드 상태 복원

### TC-SESSION-05: 새 대화 생성 ([+] 버튼)
- **절차**: 헤더 [+] 클릭
- **기대**: 빈 채팅 화면 (chat-start), 예시 칩/카드, 목록에 아직 미등록

### TC-SESSION-06: 첫 메시지 전송 후 목록 등록
- **절차**: 새 대화에서 첫 메시지 전송 → [☰]으로 목록 복귀
- **기대**: 방금 시작한 대화가 목록 최상단 `active` 표시

### TC-SESSION-07: 세션 삭제
- **절차**: 세션 항목 hover → [🗑️] 클릭
- **기대**: 1.5초 [✓] 표시 → 목록에서 제거 (낙관적 UI), 서버 `DELETE /conversations/:id` 전송

### TC-SESSION-08: 삭제된 대화 복원 불가
- **절차**: 대화 삭제 후 페이지 새로고침
- **기대**: 삭제된 대화 미표시

### TC-SESSION-09: 세션 목록 10개 제한
- **사전**: 15개 이상 대화 이력
- **기대**: 최근 10개만 표시

### TC-SESSION-10: 세션 목록 ↔ 채팅 왕복
- **절차**: 채팅 중 [☰] → 목록 → 다른 대화 클릭 → [☰] → 원래 대화 클릭
- **기대**: 양쪽 대화 상태 보존

### TC-SESSION-11: 세션 제목 자동 생성
- **절차**: "내일 6시 20명 학생회 회의" 입력
- **기대**: 세션 제목 슬롯 기반 자동 생성 (예: "5/27 학생회 회의")

### TC-SESSION-12: 상대시간 표시 정확성
- **확인**: "방금 전", "1시간 전", "3일 전", "2주 전" 등 적절 변환

## 5. P1 핵심 예약 흐름 — 정상 케이스 (14건)

> 우선순위: TC-FLOW-01~11은 **Alpha Must Pass**. TC-FLOW-12~14는 이번 라운드에서는 실제 저장 없이 submit 직전 상태까지만 확인하며, 실제 제출 완료 검증은 **Deferred**.

### TC-FLOW-01: 원샷 완전 입력 → 검색 시작
- **입력**: "내일 18시부터 20시까지 20명"
- **기대**: 모든 필수 슬롯 추출 → `ready_to_search: true` → SearchProgressCard 표시, GLS 탭 진입

### TC-FLOW-02: 멀티턴 — 인원 누락
- **입력**: "내일 6시 회의실 예약해줘"
- **기대**: 봇 "몇 명이서 사용하시나요?", phase: `slots-count`

### TC-FLOW-03: 멀티턴 — 종료시간 누락
- **입력**: "내일 6시 20명"
- **기대**: 봇 "몇 시까지 사용하시나요?" + 힌트 칩 ["20시까지", "2시간", "한 시간만"]

### TC-FLOW-04: duration 기반 종료시간 계산
- **입력**: 시작 18시 + "2시간"
- **기대**: `end_time = "20:00"` 정확 계산

### TC-FLOW-05: 모든 슬롯 순차 수집
- **입력**: "회의실 예약해줘" (모든 슬롯 누락)
- **기대**: 인원 → 날짜 → 시간 순서로 되묻기, 이전 답변 유지

### TC-FLOW-06: 힌트 칩 클릭 → 자동 전송
- **절차**: 힌트 칩 클릭
- **기대**: 칩 텍스트가 사용자 메시지로 즉시 전송 (입력란에 채우는 게 아님)

### TC-FLOW-07: SearchProgressCard 진행 표시
- **사전**: 슬롯 완성 → 검색 시작
- **기대**: 후보 리스트 — 검증 중 회전 아이콘, 완료 ✓/✗, 진행바 N/M, GLS 탭 실제 동작

### TC-FLOW-08: 가용 공간 발견 → RecommendationCard
- **기대**: 건물명, 호실, 층, 정원, 날짜/시간 표시
- **확인**: `useJojikName` 있으면 학과 우선 경고, `contents` 있으면 공지문 표시

### TC-FLOW-09: 신청 메타 수집 (meta-collect)
- **사전**: 추천 카드 후 (P2 추천 없거나 거절)
- **기대**: 봇 "신청서에는 어떤 단체의 어떤 행사로 넣을까요?"
- **후속**: "SW학생회 운영회의" → DraftCard 생성

### TC-FLOW-10: DraftCard 표시
- **기대**: 행사구분/주관단체/행사명/행사인원/사용목적 5줄 그리드, 빈 값 "미입력"
- **확인**: [GLS 제출] [수정] 버튼, 힌트 칩

### TC-FLOW-11: 초안 메타 수정
- **입력**: "행사명을 정기회의로"
- **기대**: DraftCard 갱신, 이전 카드 superseded (opacity 0.55, "교체됨" 태그)

### TC-FLOW-12: 제출 진행 (SubmitProgressCard)
- **절차**: "제출" 또는 [GLS 제출] 클릭
- **기대**: filling → saving → saved 전이, GLS 탭에서 폼 자동 채움 관찰

## 24. 버그 분류 기준

### Blocker
- 사용자 확인 없이 실제 GLS 제출
- 타 사용자 대화/신청 정보 접근
- 잘못된 날짜/시간/공간으로 제출
- 제출 실패를 성공으로 표시
- submit 금지 테스트 중 실제 예약 신청이 발생

### Critical
- 정상 예약 플로우 중간 진행 불가
- 로그인 후 재개 불가
- 후보 있음에도 항상 후보 없음
- GLS 폼 필수값 누락

### Major
- 세션 복원 실패
- P2/P3 잘못된 이력 기반 추천
- UI 주요 버튼/카드 사용 불가
- LLM 실패 시 사용자 안내 없음

### Minor
- preview/title 품질 낮음
- 상대시간 표시 어색
- 카드 애니메이션/태그 불일치
- 긴 텍스트 ellipsis 미흡

## 26. 알파 테스트 운영 가이드

- 이번 라운드에서는 실제 제출을 수행하지 않는다. 참여자에게 자동화 범위가 "신청 직전까지"임을 설명한다.
- 테스트용 단체/행사명에 `[테스트]`를 포함한다.
- 예약 플로우 날짜는 실행일 기준 최소 1주일 이후로 선택한다.
- GLS 모달은 `저장`이 아니라 상단 닫기 버튼으로 종료한다.
- 별도 controlled submit run을 수행할 때만 실제 공간을 불필요하게 점유하지 않도록 시간대를 조율하고, 제출 완료 후 GLS에서 실제 신청 내역을 반드시 확인한다.
- 실패 시 다음 정보를 수집한다:
  - 사용자 입력 원문
  - 표시된 추천 공간
  - GLS URL 상태
  - 사이드패널 스크린샷
  - Extension service worker 콘솔 로그
  - 서버 로그 timestamp
